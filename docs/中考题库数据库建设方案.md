# 中考数学真题题库数据库建设 — 实现方案

> **范围**：从试卷 Word（.doc/.docx）→ 结构化题库  
> **学科**：初中数学（首期），架构预留多学科扩展  
> **目标**：产出可供智能练习、诊断、Tutor 与学习引擎消费的真题/模拟题资产  
> **状态**：已实现，后台「题库与试卷管理 → 真题题库」可操作  
> **文档同步**：与当前代码实现对齐（2026-07-24）

---

## 1. 系统定位与边界

### 1.1 在产品中的位置

真题题库属于产品设计中「教育知识资产层」的题库知识库，服务后续：

- 能力诊断施测与选题  
- 智能练习分层训练  
- 学习规划中的薄弱强化  
- AI Tutor 错因/讲解上下文  

当前阶段完成的是 **后台资产建设**：上传 → 结构化拆题 → 人工审核编辑。  
**不做**：学生端刷题 UI、LLM 自动生成解析、自动挂载知识点（字段已预留）。

### 1.2 与知识点库的关系

| 维度 | 知识点库 | 真题题库 |
|------|---------|---------|
| 主输入 | 课标/教材 PDF | 试卷 Word |
| 核心产出 | `knowledge_points` / `knowledge_relations` | `exam_papers` / `questions` |
| 关联方式 | — | `Question.knowledge_point_ids`（JSON 列表，可人工填写） |
| 解析策略 | 正则 + LLM 分类/匹配 | **规则拆题**（标记驱动答案/解析分离，无 LLM） |

### 1.3 「解析」一词的含义

本模块中的「解析」有两层意思，文档统一按以下区分：

| 用语 | 含义 |
|------|------|
| **试卷解析** | 将 Word 拆成结构化题目并入库（`parse_status`） |
| **试题解析（analysis）** | 题目字段 `analysis`，来自 Word 中的 `【解析】/【解答】/【分析】` 等标记 |

当前实现 **不会** 用大模型为缺解析的题目自动补写 `analysis`。

## 3. 数据模型设计

### 3.1 ExamPaper（试卷）

```python
# apps/backend/app/models/question.py

class ExamPaper(Base):
    __tablename__ = "exam_papers"

    id                 # INTEGER PK
    title              # VARCHAR(500) 试卷标题
    paper_type         # VARCHAR(30) real(真题) / mock(模拟题)
    source             # VARCHAR(500) 来源说明，如：2024年XX市中考数学卷
    grade              # VARCHAR(20) 年级，如：九年级
    subject            # VARCHAR(20) 默认「数学」
    year               # VARCHAR(10) 年份
    region             # VARCHAR(100) 地区
    original_filename  # 上传原始文件名
    stored_filename    # 磁盘存储名（UUID + 扩展名）
    total_questions    # 解析得到的题目总数
    parse_status       # pending / parsing / parsed / failed
    parse_error        # 失败时的错误信息
    created_at / updated_at
```

### 3.2 Question（题目）

```python
class Question(Base):
    __tablename__ = "questions"

    id                   # INTEGER PK
    exam_paper_id        # FK → exam_papers.id
    bank_type            # real / mock（通常继承试卷 paper_type）
    question_type        # choice / fill / answer / proof
    question_number      # 卷内题号
    content              # 题干（可含 [IMG:xxx] 占位符）
    options              # JSON，如 {"A":"...","B":"..."}；可含图片占位
    answer               # 答案（简短，如 "A"、"x=3"）
    analysis             # 解析/解答过程（详细文字，可含图片占位）
    difficulty           # 1–5，默认 3
    score                # 分值（可选）
    knowledge_point_ids  # JSON：关联知识点 ID 列表（人工填写，待自动化）
    ability_dimension    # 能力维度：计算/记忆/推理/理解/综合应用（预留）
    source               # 来源说明（常拷贝自试卷 source）
    images               # JSON：本题引用的图片文件名列表
    status               # draft / reviewed / published
    created_at / updated_at
```

### 3.3 题目类型枚举

| 值 | 含义 | 识别来源 |
|----|------|---------|
| `choice` | 选择题 | 大题名含「选择」，或成功抽出 A–D 选项 |
| `fill` | 填空题 | 大题名含「填空」，或题干含 `____` / `（  ）` |
| `answer` | 解答/计算/问答/应用/综合 | 大题名映射；默认兜底类型 |
| `proof` | 证明题 | 大题名含「证明」 |

### 3.4 文件与图片存储约定

```
{UPLOAD_DIR}/
└── papers/
    ├── {uuid}.docx                    # 原始试卷
    └── paper_{paper_id}_images/
        ├── img_001.png
        ├── img_002.jpg
        └── ...
```

前端访问路径：`/uploads/papers/paper_{paperId}_images/{filename}`  
后端通过 FastAPI `StaticFiles` 挂载 `UPLOAD_DIR` 到 `/uploads`。

## 4. 试卷解析流水线

### 4.1 总体流程

```
用户上传 Word（.doc/.docx）+ 元数据（标题/年份/地区等）
        ↓
创建 ExamPaper（parse_status=pending），落盘存储文件
        ↓
BackgroundTasks → _parse_paper_background(paper_id, file_path)
        ↓
parse_status = parsing
        ↓
word_parser.parse_exam_word(file_path, image_dir)
  ① .doc → 必要时 COM 转 .docx（Windows + pywin32）
  ② 抽取全部嵌入图 → image_map{rId → filename}
  ③ 逐段提取富文本（字 + [IMG:] + OMML 公式文字）
  ④ 过滤试卷头部 / 须知 / 「参考答案与试题解析」标题等
  ⑤ 识别大题类型 + 题号切分
  ⑥ 抽选项；分离【答案】【解析】等标记
        ↓
批量写入 Question；更新 total_questions、parse_status=parsed
失败则 parse_status=failed，记录 parse_error
```

### 4.2 重新解析

`POST /api/questions/papers/{id}/reparse`：

1. 校验文件仍在磁盘  
2. 删除该卷下全部旧题目  
3. 重置 `parse_status=pending`、`total_questions=0`  
4. 再次投入后台解析任务  

### 4.3 删除试卷

删除试卷时级联：关联题目、磁盘 Word、对应 `paper_{id}_images` 目录。

## 5. word_parser 核心设计

**文件位置**：`apps/backend/app/services/word_parser.py`

### 5.1 设计原则

1. **标记驱动**：答案/解析依赖 Word 内已有结构标记，不臆造内容  
2. **图文同位**：图片不以附件列表孤存，而以内联 `[IMG:filename]` 占位保留位置  
3. **先进入题目区再认题号**：避免「考生须知」里的 1. 2. 3. 被误切成题  
4. **可降级**：无题号结构时，整篇可兜底成 1 道题（便于排障）

### 5.2 图片与公式

| 来源 | 处理 |
|------|------|
| DrawingML (`a:blip`) | 按 rId 映射到已保存图片 |
| VML (`v:imagedata`) | 老式公式/嵌入图，同样映射 |
| WMF/EMF/BMP | 尽量转 PNG（Pillow）；失败则保留原 blob |
| OMML (`m:oMath`) | 提取公式内纯文本拼入题干（非 LaTeX 还原） |

### 5.3 非题目内容过滤

命中以下关键词的行会被跳过（节选）：

`答题前`、`考生须知`、`注意事项`、`考试时间`、`满分`、`答题卡`、`密封线`、`参考答案与试题解析`、`选择题部分`、`非选择题部分` 等。

另：纯 1–3 位数字行视为页码跳过。

### 5.4 大题与题号

**大题**（`SECTION_RE` / 兜底正则）：

```
一、选择题…… → choice
二、填空题…… → fill
三、解答题…… → answer
…
```

**题号**：

```
1． / 1. / 1、 / 第1题
```

仅在已识别大题（`started=True`）后，或内容具备明显题目特征时，才接受题号行。

### 5.5 选项提取

支持：

- 每行一选项：`A．xxx`  
- 一行多选项：`A．xxx  B．xxx  C．xxx  D．xxx`  
- 选项值为图片：`A．[IMG:img_003.png]`  
- 字母后直接跟图片占位、无分隔符  

### 5.6 答案与解析分离（重点）

函数：`_split_answer_analysis(content)`

| 标记族 | 写入字段 |
|--------|---------|
| `【答案】` `【答】` | `answer` |
| `【解析】` `【解答】` `【分析】` `【思路】` | `analysis` |
| `【点评】` `【评注】` | 无 analysis 时充当 `analysis` |

处理规则：

1. 以文中 **第一个** 标记位置切开：前为纯题干，后为标记区  
2. 在标记区内分别截取答案段、解析段（遇到其它标记族结束）  
3. 有解析无答案时，尝试从解析中用正则抽短答案：  
   - `故选：C`  
   - `故答案为…`  
   - `答案是/为…`  
4. 若「答案」过长（>50 字）且无独立解析，可能把长文挪到 `analysis`，短答留下 `answer`  
5. 无任何标记时，仍可尝试从全文抽「故选：X」类短答案  

> **现象说明**：选择题常带完整「本题考察…」解析；部分解答题若 Word 无标记，入库后 `answer`/`analysis` 为空，前端显示 `-`。属数据源问题，不是列表渲染丢失。

### 5.7 单题组装输出

```python
{
  "question_number": 17,
  "question_type": "choice",
  "content": "题干…可能含 [IMG:img_001.png]",
  "options": {"A": "...", "B": "...", "C": "...", "D": "..."},
  "answer": "A",
  "analysis": "本题考察…",
  "difficulty": 3,
  "images": ["img_001.png", ...],
}
```

## 6. API 接口

路由前缀：`/api/questions`（见 `app/api/__init__.py`）

### 6.1 试卷

| 方法 | 路径 | 说明 |
|------|------|------|

| POST | `/` | 手工建题 |

## 7. 前端操作流程

**页面**：`apps/frontend/admin/src/pages/questions/QuestionBank.tsx`  
**路由**：`/questions/bank`  
**菜单**：题库与试卷管理 → 真题题库  

### 7.1 推荐流程

```
1. 准备带【答案】【解析】标记的 Word 试卷（推荐 .docx）
2. 「试卷管理」→ 上传试卷 → 填写标题/年份/地区等 → 上传并解析

5. 查看详情核对图文与解析；必要时编辑补全答案、解析、知识点 ID、能力维度
```

## 10. 质量保障与已知限制

### 已实现

1. 后台异步解析，状态可追踪  
2. 图文混排位置保留（`[IMG:]`）  
3. 答案/解析标记分离 + 短答案兜底抽取  
4. 须知区题号误识别抑制  
5. 重解析、整卷删除级联清理  
6. 人工可编辑所有关键字段  

### 已知限制 / 待建设

1. **无 LLM 自动补解析**：源 Word 无标记则 `analysis` 为空  
2. **OMML 非 LaTeX**：公式仅保留纯文本，复杂式可能可读性差  
3. **知识点自动关联**：`knowledge_point_ids` 需人工或后续算法挂载  
4. **能力维度 / 审核流**：字段预留，完整 draft→reviewed→published 工作流未做  
5. **组卷 / 模拟卷编排 UI**：仅有 `paper_type=mock` 字段，无独立组卷编辑器  
6. **表格/文本框/页眉页脚**：当前以段落遍历为主，复杂排版可能漏题  
7. **多学科试卷模板差异**：规则按中考数学常见版式调优，其它学科需扩展规则

## 11. 推荐的 Word 源格式约定（给教研）

为提高入库完整度，建议源文件遵循：

1. 使用 `.docx`；大题用「一、选择题」「二、填空题」「三、解答题」等标准标题  
2. 小题用 `1．` / `2．` 等清晰题号  
3. 每题后附：  
   - `【答案】…`  
   - `【解析】…` 或 `【解答】…`  
4. 选择题选项用 `A．` `B．` `C．` `D．`  
5. 避免把解析合集单独放在文末、且与题干无一一对应标记（当前按题内联标记切分）

## 12. 扩展方向

1. **LLM 补全解析**：对 `analysis` 为空的题目，结合题干与知识点图谱生成可审核草稿  
2. **自动挂知识点**：向量检索 / 分类模型写入 `knowledge_point_ids`  
3. **难度与考频标定**：结合历年卷与答题数据校准 `difficulty`  
4. **公式 LaTeX 化**：MathML/OMML → LaTeX，前端 KaTeX/MathJax 渲染  
5. **与练习引擎对接**：按知识点、难度、题型选题 API  
6. **质检看板**：缺答案、缺解析、缺图、未挂知识点的覆盖率统计
