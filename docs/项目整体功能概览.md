# LearningSystem 项目整体功能概览（项目记忆）

> 更新时间：2026-07-28  
> 用途：供后续需求分析、开发、排错和交接时快速恢复项目上下文。  
> 信息优先级：运行代码 > 本文 > 规划文档。规划文档中的进度快照可能落后于代码。

## 1. 一句话定位

这是一个面向中考生的数学 AI 自适应学习系统。当前产品由教研管理端和学生端组成：管理端负责建设知识图谱、教材章节、真题题库及考试结构模板；学生端基于这些资产完成目标设定、动态组卷、在线答题、自动批改和能力评估。长期目标是继续形成“诊断 → 学习路径 → 动态课程 → AI Tutor → 复测”的闭环。

首期业务语境是中考数学，浙江中考、浙教版优先；数据模型中保留了科目、地区、年级等扩展字段。

## 2. 总体架构

```text
管理端 React (:5173) ─┐
                      ├─> 共享 FastAPI (:8000) ─> SQLite（开发）
学生端 React (:5174) ─┘              │
                                    ├─> uploads 文件与试卷图片
                                    └─> OpenAI 兼容 LLM API（可选）
```

- 后端：`apps/backend`，Admin 与 Student 共用一个 FastAPI 进程和数据库。
- 管理端：`apps/frontend/admin`，React 18 + TypeScript + Ant Design + Vite。
- 学生端：`apps/frontend/student`，React 18 + TypeScript + Ant Design + Vite。
- 开发数据库：默认 `apps/backend/learning_system.db`（取决于启动工作目录）；SQLAlchemy 2 async + aiosqlite。
- 生产方向：配置中和依赖中预留 PostgreSQL、Redis、Celery、pgvector，但当前核心流程主要仍是本进程 + SQLite。
- AI：通过 OpenAI 兼容接口调用，默认模型名 `deepseek-chat`；API Key、Base URL 和模型可由管理端配置。
- 文件解析：PDF 使用 PyMuPDF，可用 EasyOCR 处理扫描件；Word 试卷使用 python-docx，并处理题面、公式/图片和答案附录。

## 4. 管理端已实现功能

管理端路由统一挂在 `/api/*`，当前没有完整 Admin 登录体系；后端只明确阻止“学生 JWT”调用 Admin 写接口。

### 4.1 知识资产

- 上传课程标准、教材等 PDF，并维护文件类型、年级、学期等信息。
- 从 PDF 文本或 OCR 结果抽取知识点。
- 知识点增删改查、筛选、状态管理、简称生成。
- 构建和维护知识点关系。
- 将知识点与教材章节进行关联/标注。
- 查看知识点、关系、分类等统计。

核心入口：

- 前端：`pages/knowledge/*`
- API：`api/files.py`、`api/extraction.py`、`api/knowledge.py`、`api/chapters.py`
- 服务：`pdf_parser.py`、`extraction_service.py`、`annotation_service.py`、`chapter_toc_service.py`

### 4.2 教材章节

- 从教材目录构建章/节树。
- 查询、编辑、删除、清空和重排章节。
- 查询章节关联知识点。
- 学生端按年级阶段只读消费章树，用于标记已学范围。

### 4.3 真题与题库

- 上传 `.doc/.docx` 试卷并后台解析为试卷、题目、选项、答案、解析和图片。
- 管理试卷与题目，支持筛选、编辑、删除、批量删除、重新解析。
- AI/规则辅助将题目挂载到主知识点，并提供建议确认流程。
- AI 辅助将图片型答案改写为可判分文本，提供建议确认流程。
- AI 辅助标注题目的能力维度。
- 配置试卷计分方案。
- 从单份或多份真题生成考试结构模板及知识点—题型分值统计，支持设置默认模板。

核心入口：

- 前端：`pages/questions/QuestionBank.tsx`
- API：`api/questions.py`
- 服务：`word_parser.py`、`kp_link_service.py`、`answer_rewrite_task_service.py`、`ability_label_service.py`、`exam_template_service.py`

### 4.4 系统配置

- 配置 LLM API Key、Base URL、模型等运行参数。
- LLM 是增强项：部分流程有纯规则兜底，资产抽取/AI 标注类任务则依赖可用配置。

### 4.5 管理端占位模块

课程与资源、生成内容审核与质检、学习数据分析、用户与权限仍是占位页，没有完整业务实现。

## 5. 学生端已实现功能

学生端 API 统一前缀为 `/api/v1/student`，页面除登录/注册外都由 `RequireAuth` 保护。

### 5.1 账号与隔离

- 邮箱或手机号注册、登录，签发 JWT。
- 查看和修改昵称、密码。
- 启动时自动创建演示学生：`demo@local / demo123`，可通过环境变量覆盖。
- 所有学生目标、测评卷和答卷按 `user_id` 校验归属；越权资源按 404 处理。
- 学生 JWT 调用 `/api/*` 管理端写接口会被中间件拒绝为 403。
- 当前默认 JWT 密钥和演示账号仅适合开发环境。

### 5.2 学习目标

- 一个学生可维护多个目标，包含考试类型、科目、地区、目标分、当前估分、年级阶段、考试日期、每日学习时长。
- 可从教材章树选择已学章节，后端展开并缓存对应知识点集合。
- 支持创建、编辑、复制、归档、设置主目标。
- 目标分或已学范围变化时标记 `needs_replan`。
- 目标状态区分待测评与已测评，并记录测评事件时间线。

### 5.3 动态组卷

- 按主目标、已学知识点、题库类型和考试结构模板预览/生成诊断卷。
- 优先采用默认或匹配的真题结构模板，按题型与知识点权重分配题量和分值。
- 从真题/模拟题池选题，避免重复，并在题池不足时降级和记录警告。
- 生成 `test_papers` 与 `test_questions` 快照，避免后续源题修改影响已组试卷。
- 学生未交卷前的公开题目结构不返回标准答案和解析。

### 5.4 在线答题、保存与交卷

- 支持选择题选项、填空/解答文本；数据模型预留手写图片 URL。
- 可逐题保存或批量保存进度，支持“不确定”标记。
- 测评状态流转：`assembled → in_progress → submitted → grading → graded`。
- 目标时间线会显示组卷、答题中、批改完成等记录。

### 5.5 自动批改与结果

- 选择题按选项比对。
- 填空题按标准化文本、多答案等规则比对。
- 解答题目前主要使用文本规则；答案缺失、以公式图片为主或无法可靠判定时会标记需人工复核/不计分。
- 交卷后立即汇总得分、答对数和已判题数。
- 结果页逐题展示学生答案、正确答案、解析、来源试卷/题号、知识点、难度、能力维度和判分说明。
- 获取旧卷结果时会使用最新规则重新判分，以修复历史规则误判。

### 5.6 能力评估

- 批改后调用 `services/learning/assessment.py` 生成并保存能力评估 JSON。
- 规则评估保证基本报告可产出；配置 LLM 后可进行语言润色和增强。
- 评估失败不会阻断交卷。
- 当前评估数据随结果接口返回，学生结果页可消费；独立“报告”导航页仍是占位。

## 6. 尚未完成的核心闭环

以下是产品规划目标，但当前没有端到端实现：

- 独立、持续积累的学生知识点掌握度画像。
- 错题讲解对话与可追问 AI Tutor。
- 根据目标差距和画像生成动态学习路径、每日任务及重规划。
- 动态课程/讲义生成、资源匹配和课程学习进度。
- 薄弱点专项练习、复测和闭环更新。
- 完整的成长报告趋势页。
- 管理端正式鉴权、角色权限和学生数据运营。
- 生产级任务队列、对象存储、迁移体系、监控与部署方案。

因此，当前最准确的产品阶段描述是：

```text
资产建设（较完整）
  → 学生目标（已完成）
  → 动态组卷（已完成）
  → 在线答题（已完成）
  → 规则自动批改（已完成，主观题能力有限）
  → 当次结果 + 能力评估（已实现基础版）
  → 学习路径/课程/Tutor/复测（待开发）
```

## 7. 关键数据域

### 7.1 共享教育资产

- `uploaded_files`：上传资料。
- `textbook_chapters`：教材章/节目录。
- `knowledge_points`、`knowledge_relations`：知识图谱。
- `exam_papers`、`questions`：源试卷与题库。
- `exam_score_schemes`：计分方案。
- `exam_structure_templates`、`exam_kp_score_stats`：考试结构与知识点/题型权重。
- 多类任务/建议表：知识点挂载、答案改写、能力标签等。

### 7.2 学生私有数据

- `users`：账号与角色。
- `learning_goals`、`goal_learned_chapters`：目标与已学范围。
- `goal_result_records`：目标上的测评时间线。
- `test_papers`：学生诊断卷、状态、得分、能力评估 JSON。
- `test_questions`：卷内题目快照。
- `test_answers`：学生作答和判分结果。

## 8. 核心调用链

### 8.1 管理端资产建设

```text
上传 PDF/Word
  → PDF/OCR 或 Word 富文本解析
  → 知识点/章节/试卷/题目入库
  → 教研编辑与 AI 辅助标注
  → 题目挂主知识点
  → 生成并设定考试结构模板
  → 学生端资产 readiness 达标
```

### 8.2 学生测评

```text
注册/登录
  → 创建目标并选择已学章节
  → 章节展开为已学知识点
  → 按考试模板分配题型/知识点配额
  → 从共享题库选题并生成私有试卷快照
  → 答题与暂存
  → 交卷
  → 规则判分
  → 保存得分、结果记录和能力评估
  → 结果页查看逐题反馈
```

## 11. 后续开发时的重要约束

1. 学生只能读共享资产，不能通过学生 API 修改知识点、题库、模板。
2. 学生私有资源的查询和修改必须始终带 `user_id` 归属过滤。
3. 未交卷接口不能泄露答案、解析或评分信息。
4. 组卷必须保存题目快照，不能让源题后续编辑破坏历史卷。
5. 题库、知识点、章节和模板是同一条资产链，修改字段时要检查管理端、组卷服务和学生端契约。
6. 试卷图片依赖源试卷 ID 和 `/uploads` 路径展开；不要只改前端图片拼接逻辑。
7. SQLite 的 `db_migrate.py` 是当前兼容迁移机制；新增 ORM 字段时不能只改模型。
8. 自动批改对主观题能力有限，不能把规则比对包装成可靠的全自动主观题评分。
9. 规划文档中的“当前进度”可能滞后，判断功能是否存在应同时检查前端路由、API、服务和 ORM。
10. `packages/ai-engine` 与 `packages/shared` 当前只是占位，不要误认为已有独立 AI 引擎包。
