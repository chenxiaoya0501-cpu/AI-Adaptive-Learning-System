# 中考数学知识点数据库建设 — 实现方案

> **范围**：从课标 PDF + 教材 PDF → 结构化知识库  
> **学科**：初中数学（浙教版优先，预留多学科扩展）  
> **目标**：产出可供 AI 学习引擎消费的知识图谱数据  
> **状态**：已实现，后台管理系统可操作  
> **文档同步**：与当前代码实现对齐（2026-07-25）

---

## 1. 系统架构

知识库建设作为后台管理系统中的完整子系统，由三条可独立触发的异步任务链组成：

| 任务类型 | 触发入口 | 核心服务 | 主要产出 |
|---------|---------|---------|---------|
| `knowledge_extraction` | 知识抽取页 → `/api/extraction/start` | `extraction_service` | 课标条目 → 知识点（领域/分类/能力等级） |
| `annotation` | 知识点管理页「标注章节/年级段」→ `/api/knowledge/annotate-chapters` | `annotation_service` | 教材匹配 → `grade` / `chapter` |
| `relation_extraction` | 知识抽取页 → `/api/extraction/start` | `extraction_service` | 知识点间关系边 |

> **重要演进**：教材年级/章节标注已从「知识点抽取」中拆出，独立为 `annotation_service`。  
> 当前 `knowledge_extraction` **仅处理课标 PDF**；教材标注在知识点管理页单独启动。

## 2. 数据模型设计

### 2.1 KnowledgePoint（知识点）

```python
# apps/backend/app/models/knowledge.py

class KnowledgePoint(Base):
    __tablename__ = "knowledge_points"

    id                # VARCHAR(50) PK, 如 MATH-01-003
    subject           # VARCHAR(20) 学科类别（数学 / 英语 / 物理…）
    domain            # VARCHAR(50) 知识领域：数与代数/图形与几何/统计与概率/综合与实践
    category_1        # VARCHAR(100) 一级分类，如：数与式 / 方程与不等式 / 函数
    category_2        # VARCHAR(100) 二级分类，如：(1) 有理数 / (2) 实数
    name              # VARCHAR(500) 知识点内容描述（课标条目原文）
    typical_questions # TEXT 典型题目引用，来自课标中的"例XX"
    grade             # VARCHAR(20) 年级段，如：七年级上册（由标注任务写入）
    chapter           # VARCHAR(200) 所属教材章节，如：第一章 有理数
    prerequisites     # TEXT 依赖知识点 ID 列表，逗号分隔（字段已预留）
    cognitive_level   # VARCHAR(20) 能力等级：了解/理解/掌握/运用
    source            # VARCHAR(50) 数据来源：curriculum / textbook / manual
    status            # VARCHAR(20) draft / reviewed / published
    version           # INTEGER 版本号
    created_at        # TIMESTAMP
    updated_at        # TIMESTAMP
```

### 2.2 KnowledgeRelation（知识点关系）

```python
class KnowledgeRelation(Base):
    __tablename__ = "knowledge_relations"

    id              # INTEGER PK, 自增
    from_point_id   # FK → knowledge_points.id（前置知识点）
    to_point_id     # FK → knowledge_points.id（后续知识点）
    relation_type   # VARCHAR(30)：prerequisite / related / extends / contains
    weight          # FLOAT 关系权重，默认 1.0
    created_at      # TIMESTAMP

    # 唯一约束：(from_point_id, to_point_id, relation_type)
```

### 2.3 TypicalQuestion（典型题目）

```python
class TypicalQuestion(Base):
    __tablename__ = "typical_questions"

    id                  # INTEGER PK, 自增
    knowledge_point_id  # FK → knowledge_points.id
    question_content    # TEXT 题目内容
    answer              # TEXT 答案
    analysis            # TEXT 解析
    difficulty          # SMALLINT 难度 1-5
    question_type       # VARCHAR(30) 选择/填空/解答
    source              # VARCHAR(200) 题目来源（如：2024浙江中考第15题）
```

> **实现现状**：表结构已建；课标抽取会把「例XX」引用写入知识点的 `typical_questions` 文本字段。  
> 独立题面入库（`typical_questions` 表灌题）尚未接入主流水线。

### 2.5 知识点 ID 编码规则

```
格式：{学科}-{领域编号}-{序号}
示例：MATH-01-003

学科代码：
  MATH = 数学
  ENG  = 英语（预留）
  CHN  = 语文（预留）
  PHY  = 物理（预留）

领域编号：
  01 = 数与代数
  02 = 图形与几何
  03 = 统计与概率
  04 = 综合与实践
  00 = 未分类

序号：三位数字，按库内已有点数递增，从 001 起
```

当前实现中 `_generate_point_id(domain, seq)` 固定前缀为 `MATH-`；学科字段 `subject` 可从课标文件名识别（英语/语文/物理），但 ID 前缀尚未按学科切换。

### 2.6 关系类型

| 关系 | 含义 | 示例 |
|------|------|------|
| prerequisite | 前置依赖（学 B 之前必须先学 A） | 等式性质 → 一元一次方程 |
| related | 关联/类比 | 一元一次方程 ↔ 一元一次不等式 |
| extends | 进阶（B 在 A 基础上扩展） | 全等三角形 → 相似三角形 |
| contains | 包含（章节 → 知识点） | 三角形章 → 三角形内角和 |

## 3. 知识建设流水线（三条任务）

### 3.1 总体流程

```
① 系统配置：填写 LLM API Key / Base URL / Model
        ↓
② 资料上传：课标 PDF（curriculum）+ 教材 PDF（textbook）
        ↓
③ 知识点抽取（knowledge_extraction）—— 仅课标
   正则预提取 ①②③… → LLM 分类 → 入库 KnowledgePoint
        ↓
④ 章节/年级标注（annotation）—— 多本教材综合
   按章合并切片 → LLM 匹配「首次正式教学」→ 投票选最佳 grade/chapter
        ↓
⑤ 人工审核：知识点管理页筛选、编辑、补全
        ↓
⑥ 关系抽取（relation_extraction）—— 按领域分批
   LLM 输出 from_id/to_id → 校验后写入 KnowledgeRelation
```

### 3.2 关键设计决策：正则预提取 + LLM 分类

**核心思想：LLM 不负责「发现」知识点（易幻觉），只负责对已精确提取的条目做分类。**

```
课标 PDF 文本（含 OCR 加速路径，见 3.3）
    ↓
正则引擎：逐行扫描，维护层级上下文
  - 自动识别：知识领域标题（数与代数/图形与几何/…）
  - 自动识别：一级分类（1. 数与式 / 2. 方程与不等式 / …）
  - 自动识别：二级分类（(1) 有理数 / (2) 实数 / …）
  - 精确提取：①②③… 编号条目的完整文本（支持跨行）
  - 自动提取：典型题目引用（例1～例XX）
    ↓
输出：numbered_items[]（已带 domain_hint / category_1_hint / category_2）
    ↓
分批发送给 LLM（默认每批 10 条，可配置 extraction_batch_size）
  - 输入：编号条目 + 系统自动识别的上下文提示
  - LLM 任务：确认/修正 domain, category_1, category_2, cognitive_level
  - 输出：严格 JSON（response_format: json_object）
  - 对齐策略：优先按 number 匹配分类结果；缺失时回退下标
  - 并发：asyncio.Semaphore(extraction_llm_concurrency)，默认 2
  - 进度：PDF/OCR 阶段同步回写 2%~45%；LLM 阶段 45%~99%
    ↓
入库：按 name 精确去重
  - 已存在 → _supplement_point（只补缺失字段，不覆盖）
  - 不存在 → 新建，source=curriculum，status=draft
```

### 3.3 OCR 扫描版 PDF 处理（含加速）

```
PDF 打开（PyMuPDF）
    ↓
检测是否为扫描版（前 10 页中 ≥70% 文字极少且有图片）
    ↓
├─ 文字版 → 直接 page.get_text()
│
└─ 扫描版：
       ↓
   课标默认只 OCR 课程内容页（总页数约 25%~55%），跳过总论和附录
       ↓
   缓存命中？（uploads/.ocr_cache/，键=文件 sha256 + 页范围 + DPI）
     ├─ 命中 → 直接返回文本，进度 stage=ocr_cache
     └─ 未命中 → EasyOCR 流水线：
           ① 全局单例 Reader（懒加载，有 CUDA 时自动 gpu=True）
           ② 多线程并行渲染页面（ocr_workers，默认 2；每线程独立打开 PDF）
           ③ 推理加锁串行（Reader 非线程安全），与渲染形成流水线重叠
           ④ DPI 默认 200；结果写入 OCR 缓存
       ↓
   OCR 特殊格式适配：
     - ① 被识别为 "0" + 知识点动词
     - ②③④… 被识别为 "@" + 知识点动词
     - 选学 * 开头条目一并识别
     - 正则引擎同时适配原生圆圈数字与 OCR 格式
```

> **设计取舍**：OCR 推理共享单例 + 加锁，避免多 Reader 占满内存；通过并行渲染与缓存换取速度。

### 3.4 教材章节/年级标注（独立任务）

入口：`POST /api/knowledge/annotate-chapters`  
实现：`annotation_service.run_annotation_task`

> **性能演进（2026-07-25）**：旧实现按「小节切片」串行调用 LLM（六本教材可达百余次请求，且每次附带全部知识点全文），易长时间卡在中等进度。现行改为 **按章合并 + 紧凑知识点列表 + LLM 超时保护**。

```
选择多本教材 PDF + 模式（overwrite / append）
        ↓
创建 ExtractionTask(task_type=annotation)
        ↓
解析阶段（progress≈2%~5%）：
  ① extract_pdf_text（复用 OCR 缓存/加速）
  ② chunk_textbook_pdf（按「第X章」/「X.X 节」细切）
  ③ _merge_chunks_by_chapter：同章合并，单章正文上限约 5000 字
     → 调用次数从「节级」降为「章级」（数量级下降）
        ↓
逐本教材 LLM 匹配（progress≈5%~90%）：
  ① 从文件名或上传字段解析 grade_info（如：七年级上册）
  ② 每批合并 1~2 章（chapters_per_batch；复用 extraction_batch_size，过大时压到 2）
  ③ 知识点列表紧凑格式：ID|短名称（截断至约 60 字），降低 token
  ④ LLM 任务：判断哪些知识点在本册被「首次正式教学」
  ⑤ 输出：point_id（优先）/ point_name / grade / chapter / confidence
  ⑥ 单次 LLM 超时（默认 120s）；失败跳过该批并继续，进度照常推进
  ⑦ result_summary.detail 实时展示：当前教材 · 批次 i/n · 候选数
        ↓
收集候选 votes：{知识点名: [(grade, chapter, confidence, grade_order), ...]}
        ↓
综合投票 _select_best_match：
  - 同 (grade, chapter) 累加：confidence 分 + 年级越早加分
  - 取最高分作为「首次教学」落点
        ↓
回填到库内知识点：
  - 优先 point_id 精确定位；否则 _fuzzy_match_point（精确 → 包含 → 前缀）
  - overwrite：覆盖 grade/chapter
  - append：分号拼接新值，保留已有标注
```

设计要点：

1. **首次正式教学**：Prompt 明确要求不要把「复习/提及」当成首次教学。
2. **多教材综合**：避免单本教材误匹配；早期年级 + 高置信优先。
3. **与课标抽取解耦**：可在抽取完成后反复重标，无需重跑课标。
4. **按章合并**：保证效果的前提下显著缩短墙钟时间，避免任务假死感。
5. **标注结果在全部教材跑完后统一写库**：进行中年段/章节列可能仍为空，属预期行为。

### 3.5 关系抽取

```
加载全部 KnowledgePoint，建立 valid_ids 集合
        ↓
按 domain 分组
        ↓
组内再按 BATCH_SIZE=30 分批（避免 prompt 过长）
        ↓
逐批调用 LLM（RELATION_EXTRACTION_PROMPT）
  - 输入格式：- [MATH-01-001] 知识点名称（分类，年级）
  - 输出：from_id / to_id / type / reason（必须复制列表中的真实 ID）
        ↓
校验：
  - from_id、to_id ∈ valid_ids
  - from_id ≠ to_id
  - type ∈ prerequisite|related|extends|contains（非法则回落 prerequisite）
  - 同 from+to+type 不重复插入
        ↓
写入 knowledge_relations，更新进度与 result_summary
```

## 4. LLM 调用方案

### 4.1 Prompt 模板（与代码一致）

| Prompt | 所在文件 | 作用 | 输入 | 输出 |
|--------|---------|------|------|------|
| `CURRICULUM_CLASSIFY_PROMPT` | `extraction_service.py` | 为正则预提取条目做分类 | 编号条目 + 上下文提示 | domain / category_1 / category_2 / cognitive_level |
| `TEXTBOOK_MATCHING_PROMPT` | `annotation_service.py` | 匹配首次教学年级与章节 | 紧凑知识点列表 + 按章教材文本 | point_id / point_name / grade / chapter / confidence |
| `RELATION_EXTRACTION_PROMPT` | `extraction_service.py` | 识别依赖/关联/进阶 | 带 ID 的知识点列表 | from_id / to_id / type / reason |

### 4.2 LLM 客户端封装

```python
# apps/backend/app/services/llm_client.py

class LLMClient:
    - 基于 OpenAI 兼容接口（AsyncOpenAI）
    - 默认 DeepSeek（base_url: https://api.deepseek.com/v1）
    - 旧模型名自动映射：deepseek-chat → deepseek-v4-flash 等
    - response_format={"type": "json_object"} 约束 JSON
    - JSON 解析失败时，自动从文本中截取 [{…}] 或 {…}
    - temperature 默认 0.1；max_tokens 默认 4096（钳制 256~8192）
    - 超时保护：默认 120s（asyncio.wait_for + 客户端 timeout），防止任务永久挂起
    - 配置项通过后台 UI 写入 system_configs，任务启动时读取，无需重启
```

### 4.3 可配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| llm_api_key | - | API 密钥（必填，否则任务失败） |
| llm_base_url | https://api.deepseek.com/v1 | API 地址 |
| llm_model | deepseek-v4-flash（旧名 deepseek-chat 自动映射） | 模型名称 |
| llm_temperature | 0.1 | 生成温度 |
| llm_max_tokens | 4096 | 最大输出 token |
| extraction_batch_size | 10 | 课标：每批条目数；标注：复用为每批章数（过大时压到 2） |
| extraction_llm_concurrency | 2 | 课标分类 LLM 并发数（1~8） |
| ocr_workers | 2 | 扫描版 PDF 并行渲染线程数（1~8） |
| ocr_cache_enabled | true | 是否启用 OCR 结果缓存以加速重跑 |

## 7. 前端操作流程

### 7.1 推荐完整流程

```
1. 系统配置 → 运行设置
   填入 LLM API Key、Base URL、Model 等

2. 知识图谱管理 → 资料上传
   - 上传课程标准 PDF（file_type=curriculum）
   - 上传教材 PDF（file_type=textbook，可指定年级/学期；也可从文件名解析）

3. 知识图谱管理 → 知识抽取
   新建任务 →「知识点抽取」→ 勾选课标 PDF（可多选课标）
   等待完成（进度条实时更新）

4. 知识图谱管理 → 知识点管理
   查看抽取结果；可筛选、编辑、手动新建、清空重抽
   点击「标注章节/年级段」→ 多选教材 → overwrite/append → 启动 annotation 任务

5. 知识图谱管理 → 知识抽取（再次）
   新建任务 →「关系抽取」
   自动分析库内知识点依赖关系

6. 知识图谱管理 → 关系管理 / 图谱概览
   查看、手工增删关系；查看统计分布
```

### 7.2 关键交互细节

- **课标抽取幂等**：同名知识点不重复创建，只补充空字段。
- **标注可重复跑**：`overwrite` 重写；`append` 用 `; ` 拼接多值。
- **任务统一落库**：抽取、关系、标注都写入 `extraction_tasks`，可在抽取任务页看到 `annotation` 记录。
- **进度可观测**：运行中任务的「结果」列展示 `result_summary.detail`（如 OCR 页进度、LLM 批次、候选数）。
- **创建时间显示**：SQLite `CURRENT_TIMESTAMP` 为 UTC；前端按北京时间格式化，避免慢 8 小时。
- **系统配置**：可调 batch / LLM 并发 / OCR 线程与缓存；列表接口会补齐缺失的默认配置项。

### 8.1 课标入库去重

### 8.2 标注阶段匹配（ID 优先 + 模糊降级）

```
优先：LLM 返回 point_id 且存在于库 → 直接定位
    ↓ 无 ID 或未命中
使用 point_name → _fuzzy_match_point：
  Level 1 - 精确匹配：name == existing_name
      ↓ 失败
  Level 2 - 包含匹配（双向，长度>8）
      ↓ 失败
  Level 3 - 前缀匹配（前15字符，长度>=8）
      ↓ 失败
  返回 None（跳过该条匹配）
```

### 8.3 多教材投票

```python
# annotation_service._select_best_match
# score = confidence(high=3/medium=2/low=1) + 年级越早加分
# 同一 (grade, chapter) 多次出现则累加
```

保证「首次教学」尽量落在更早年级、更高置信的章节上。

## 10. 核心代码模块详解

### 10.1 pdf_parser.py — PDF 解析与正则预提取

**文件位置**：`apps/backend/app/services/pdf_parser.py`

```
extract_pdf_text(pdf_path, ocr_workers=2, use_ocr_cache=True, progress_callback=...)
  ├── _detect_scanned_pdf(doc)
  ├── 文字版 → page.get_text("text")
  └── 扫描版 → _ocr_pdf_pages(pdf_path, page_range, workers, dpi, use_cache)
                 ├── _find_curriculum_content_range → 默认只 OCR 25%~55%
                 ├── OCR 缓存（sha256 + 范围 + DPI）命中则跳过识别
                 ├── _get_easyocr_reader() 全局单例（CUDA 可用则 GPU）
                 └── ThreadPoolExecutor：并行渲染 + 加锁推理
       ↓
extract_curriculum_numbered_items(pages)
  ├── _detect_ocr_format(full_text)
  ├── 逐行扫描，维护 domain → category_1 → category_2
  ├── 原生①②③ 或 OCR 的 0/@/* 条目识别
  ├── 跨行拼接条目正文，剥离「例XX」引用到 typical_question
  └── cat2_to_cat1 / cat2_to_domain 映射表回填空缺分类
       ↓
chunk_curriculum_for_classification(items, batch_size)
chunk_textbook_pdf(pages, grade, semester)   # 供标注服务使用（节级切片）
```

#### 10.1.1 扫描版检测

前 10 页中，若 ≥70% 页面文字 &lt;20 字符且存在图片，判定为扫描版。

#### 10.1.2 OCR 范围裁剪与加速

课标 PDF（如《义务教育数学课程标准（2022 年版）》）约 189 页时，课程内容大致在 25%~55% 页区间；默认只 OCR 该区间。

额外加速手段：

| 手段 | 说明 |
|------|------|
| Reader 单例 | 避免每次任务重新加载模型 |
| 并行渲染 | `ocr_workers` 线程各自 `fitz.open` 渲页，推理加锁 |
| 结果缓存 | `uploads/.ocr_cache/`，重跑同一文件可秒级跳过 OCR |
| 进度回调 | `ocr_init` / `ocr` / `ocr_cache` / `text`，供任务页展示 |

#### 10.1.3 OCR 条目识别策略

| 课标原文 | OCR 常见结果 | 匹配策略 |
|----------|-------------|---------|
| ① | `0` + 知识点动词 | 行首 `0` + 理解/掌握/能/会… |
| ②③④… | `@` + 知识点动词 | 行首 `@` + 同上 |
| 选学 `*` | `*` + 知识点动词 | 行首 `*`，正文保留 `*` 前缀 |

#### 10.1.4 层级上下文与后处理映射

扫描时维护 `current_domain / current_cat1 / current_cat2`；提取结束后用 `cat2_to_cat1`、`cat2_to_domain` 补全空缺提示，供 LLM 分类参考。

#### 10.1.5 教材切片

`chunk_textbook_pdf` 按「第X章…」与「X.X 中文标题」切分，输出 `{content, chapter, section, grade, semester}`。  
标注服务再调用 `_merge_chunks_by_chapter` 合并为章级单元，避免节级海量 LLM 调用。

### 10.3 extraction_service.py — 课标抽取与关系抽取

**文件位置**：`apps/backend/app/services/extraction_service.py`

#### 10.3.1 任务入口

```python
def run_extraction_task(task_id: int):
    asyncio.run(_run_extraction_async(task_id))

# task_type 分发：
#   knowledge_extraction → _extract_knowledge_merged()  # 实际仅处理课标
#   relation_extraction  → _extract_relations()
```

#### 10.3.2 课标抽取 — `_extract_knowledge_merged()`

```
加载 source_file_ids → 过滤 file_type == "curriculum"
预加载 existing_points = {name: KnowledgePoint}
        ↓
for each curriculum_file:
  extract_pdf_text(..., ocr_workers, use_ocr_cache, progress_callback)
    # PDF/OCR 阶段用同步连接 _sync_update_task_progress 回写 2%~45%
  extract_curriculum_numbered_items
  chunk_curriculum_for_classification(batch_size)
  asyncio 有限并发（extraction_llm_concurrency）调用 LLM：
    llm.extract_json(CURRICULUM_CLASSIFY_PROMPT, ...)
    对齐：优先 by number，否则按下标
    新建或 _supplement_point
    更新 task.progress（45%~99%）与 result_summary.detail
        ↓
completed + result_summary={extracted_points, total_files}
```

> 函数名仍保留 `_extract_knowledge_merged`（历史命名）；教材合并逻辑已迁至 `annotation_service`。

#### 10.3.3 课标分类 Prompt 要点

- 输入条目数量与输出 `classifications` 必须一致，禁止增删条目
- 能力等级：了解 / 理解 / 掌握 / 运用（多动词取最高）
- 领域四选一：数与代数 / 图形与几何 / 统计与概率 / 综合与实践

#### 10.3.4 ID 生成

```python
def _generate_point_id(domain: str, seq: int) -> str:
    domain_codes = {
        "数与代数": "01", "图形与几何": "02",
        "统计与概率": "03", "综合与实践": "04",
    }
    return f"MATH-{domain_codes.get(domain, '00')}-{seq:03d}"
```

#### 10.3.5 关系抽取 — `_extract_relations()`

- 按 domain 分组，组内每批最多 30 个点
- Prompt 要求返回 **真实 ID**（`from_id` / `to_id`），入库前校验
- `result_summary` 含 `total_relations`、`skipped_invalid_ids`

关系 Prompt 关键规则：

1. ID 必须从列表 `[ID]` 精确复制，禁止编造  
2. 只输出确定性高的关系  
3. 每对知识点只输出一种最主要关系

### 10.4 annotation_service.py — 教材标注编排

**文件位置**：`apps/backend/app/services/annotation_service.py`

#### 10.4.1 入口与模式

```python
async def run_annotation_task(
    textbook_file_ids: List[int],
    mode: str = "overwrite",   # overwrite | append
    task_id: Optional[int] = None,

```

由 `knowledge.annotate_chapters` 创建 `ExtractionTask(task_type="annotation")` 后后台执行。

#### 10.4.2 编排加速要点（现行）

```python
_merge_chunks_by_chapter(chunks, max_chars=5000)  # 节级 → 章级
_format_points_compact(points)                    # "ID|短名称"
```

- 六本教材场景：旧方案可达百余次 LLM；按章合并后通常降至数十次量级  
- 超时/失败：单批跳过并继续，不阻塞整任务  
- `result_summary` 持续写 `detail`（教材名、批次、候选数），避免界面「假死」感  

#### 10.4.3 教材匹配 Prompt 要点（现行）

与早期「尽量多匹配」不同，现行 Prompt 强调：

1. 只匹配该章节中 **首次正式教学** 的知识点  
2. 不要匹配仅「提到」或「复习」的内容  
3. `chapter` 填章标题（来自 `[章节: ...]`），不要填小节  
4. **优先填写 `point_id`**；否则 `point_name` 从列表完整复制  
5. 输出 `confidence`: high / medium / low  
6. **宁可少匹配，不要错匹配**

```python
def _detect_grade_from_filename(filename, grade_field, semester_field) -> str:

    # "浙教版8年级下册..." → "八年级下册"
    # 兜底：上传时的 grade/semester 字段 → 默认「七年级上册」
```

## 11. 质量保障

### 已实现

1. **去重幂等**：同名知识点不重复创建；多次抽取只补空字段  
2. **幻觉控制**：知识点边界由正则界定，LLM 只做分类/匹配  
3. **分类对齐**：课标分类优先按 `number` 匹配，降低漏条/乱序错标  
4. **标注匹配**：`point_id` 优先 + 三级模糊降级  
5. **多教材投票**：置信度 + 年级先后，降低单本误标  
6. **关系 ID 校验**：拒绝伪造/越界 ID，记录 `skipped_invalid_ids`  
7. **JSON 容错**：响应解析失败时尝试截取 JSON 片段  
8. **进度可观测**：ExtractionTask.progress + `result_summary.detail` / error_message  
9. **OCR/抽取加速**：Reader 复用、并行渲染、OCR 缓存、课标 LLM 有限并发  
10. **标注加速与防挂起**：按章合并、紧凑 Prompt、LLM 超时跳过失败批次  

### 待建设

1. **覆盖率检查**：对照课标条目逐条确认是否入库  
2. **依赖环检测**：自动化检测循环 prerequisite  
3. **粒度标准**：可独立出题检测的最小单元量化规则  
4. **版本管理**：批量发布、打 tag、回滚  
5. **审核工作流**：draft → reviewed → published 完整流转  
6. **TypicalQuestion 表灌题**：从课标例题/真题结构化入库  
7. **学科 ID 前缀**：按 subject 生成 ENG-/CHN- 等（字段已预留）  
8. **更聪明的 OCR 页范围**：关键词定位「课程内容」替代固定 25%~55%  
9. **标注增量写库**：边匹配边落库，缩短「年段/章节列为空」的等待感

## 12. 与早期方案的关键差异

| 维度 | 早期/文档旧述 | 当前实现 |
|------|--------------|---------|
| 抽取方式 | LLM 从零发现知识点 | 正则预提取 + LLM 分类 |
| 教材处理 | 与课标合并在同一次 `knowledge_extraction` | 独立 `annotation` 任务 + `annotation_service` |
| 教材匹配目标 | 「尽量多匹配相关内容」 | 「首次正式教学」+ confidence + 多教材投票 |
| 标注切片粒度 | 节级切片 × 全量知识点全文（易百余次慢请求） | **按章合并** + `ID\|短名称` 紧凑列表 |
| 课标分类对齐 | 仅按下标 | **优先 number**，下标兜底 |
| 关系标识 | 按知识点名称 from/to | 按真实 ID：from_id / to_id |
| 关系批处理 | 按领域整组 | 领域内再按 30 条分批 |
| ID 格式 | 曾规划含年级 | `MATH-{领域}-{序号}` |
| 数据库 | 曾规划 PostgreSQL + pgvector | SQLAlchemy（SQLite/PostgreSQL 可切换），向量检索未接 |
| OCR | 曾规划 PaddleOCR / Mathpix；或每次冷启动串行 | EasyOCR **单例 + 并行渲染 + 缓存**；CUDA 可用则 GPU |
| LLM 健壮性 | 无明确超时 | 默认 **120s 超时**；标注失败批次可跳过 |
| 运行方式 | 独立脚本 | FastAPI 后台任务 + Web UI |
