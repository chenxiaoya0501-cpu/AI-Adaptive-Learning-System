# 学生端自适应学习闭环 — 技术方案与选型（v0.1）

> **依据文档**：[`学生端自适应学习闭环-产品方案细化.md`](./学生端自适应学习闭环-产品方案细化.md)  
> **现有基础**：后台 Admin（FastAPI + React）已具备知识点库、数学题库（Word 解析）  
> **目标**：给出可落地的系统架构、技术选型、服务拆分、数据与接口方案、异步链路与分期落地路径  
> **状态**：技术方案确认稿

---

## 1. 设计原则

| 原则 | 说明 |
|------|------|
| 资产统一 | 知识点/题库只维护一份（Admin 建设，Student 只读消费） |
| 延续现栈 | 优先复用已引入依赖（FastAPI、SQLAlchemy、OpenAI SDK、Celery、Redis、pgvector） |
| 同步快、异步重 | 组卷/交卷接口快速返回；批改、OCR、诊断、路径、课程生成走任务队列 |
| 快照不可变 | 测评卷题目/答案/解析落快照，避免题库事后修改影响历史答卷 |
| 学科可插拔 | `subject` 贯穿模型与题池过滤；首期数学，接口不写死 |
| 可观测可回放 | 组卷参数（模板、λ、algorithm_version）、LLM/OCR 调用留痕 |

## 3. 技术选型

### 3.1 选型总表

| 层级 | 选型 | 理由 | 备选 |
|------|------|------|------|
| 学生端 UI | **React 18 + TypeScript + Vite + Ant Design 5** | 与 Admin 同栈，降低人力成本 | Next.js（若要强 SEO/SSR，本产品非必须） |
| 学生端状态 | **React Query（TanStack Query）+ Zustand（轻量）** | 答卷暂存、诊断轮询、课程树请求缓存 | Redux（过重） |
| 后台 UI | 维持现有 Ant Design Admin | — | — |
| API | **Python FastAPI + Pydantic v2** | 已落地；异步友好；与 LLM/OCR 生态契合 | NestJS（需重写资产层，不建议） |
| ORM | **SQLAlchemy 2.0 async** | 已用；Alembic 已在依赖中 | — |
| 主库 | **开发 SQLite → 生产 PostgreSQL 14+** | 已可切换；统计/并发/JSON 更稳 | MySQL |
| 向量检索（P2+） | **pgvector** | requirements 已含；知识点/题干语义检索、Tutor RAG | 独立 Milvus（运维重） |
| 缓存 / 队列 Broker | **Redis 7** | Celery broker、交卷防重、组卷分布式锁、会话限流 | — |
| 异步任务 | **Celery 5 + Redis** | 已在 requirements；适合批改/OCR/长链路 | ARQ / RQ（生态较弱） |
| 认证 | **JWT（python-jose）+ refresh / 或 HttpOnly Cookie** | jose/passlib 已引入 | Auth0（早期过重） |
| 密码 | **passlib[bcrypt]** | 已引入 | — |
| LLM | **OpenAI 兼容 SDK（DeepSeek 等）** | 现有 `llm_client` 可复用扩展 | 多模型路由（后期） |
| 手写 OCR | **P1：百度/腾讯/合合 云 OCR（公式包）**；本地兜底 EasyOCR | 数学手写公式云端准确率更高；现有 EasyOCR 可作非公式兜底 | Mathpix（贵、效果好） |
| 对象存储 | **P1 本地 UPLOAD_DIR；P2 阿里云 OSS / MinIO** | 手写图与课程资源增长后迁云 | S3 兼容 |
| 实时推送 | **P1 前端轮询任务状态；P2 WebSocket / SSE** | 批改进度足够用轮询 | — |
| 可观测 | **结构化 logging + request_id；后期 OpenTelemetry** | 先够用 | Sentry |
| 部署 | **Docker Compose（api + worker + redis + postgres）** | 本地/小规模一致 | K8s（量起来再上） |

### 3.2 明确不选（首期）

| 不选 | 原因 |
|------|------|
| 微服务大拆（十几个服务） | 团队与流量不匹配；先模块化单体 |
| 图数据库（Neo4j）存知识图谱 | 现有关系表 + 拓扑算法足够；运维成本高 |
| 自研公式识别模型 | 投入过大；优先商用 OCR |
| 学生端小程序优先 | 手写上传、长文本讲解 Web 更顺；可后做 |

## 6. 关键链路技术方案

### 6.1 动态组卷（`assembly`）

```text
POST /student/tests/assemble
  → 读 primary goal、L、默认 template
  → Redis 锁 user:{id}:assemble 防重复点
  → 同步执行算法（通常 <2s）或短任务
  → 写 test_papers + test_questions 快照
  → 返回 test_paper_id
```

实现要点：

- 纯 Python 服务函数，单测覆盖 Largest Remainder / λ 混合  
- 题池查询：索引 `(subject, bank_type, question_type, primary_kp_id, status)`  
- `algorithm_version` 常量，便于对比实验  

### 6.2 答题与交卷（`exam`）

```text
PUT  /student/tests/{id}/answers/{qid}   # 自动暂存
POST /student/tests/{id}/submit
  → status=submitted
  → Celery: grading_pipeline.delay(attempt_id)
  → 前端轮询 GET /student/tests/{id}/status
```

手写图：`POST /student/uploads/handwriting` → 存对象存储 → 返回 URL 写入 answer。

本地草稿：前端 `localStorage` / IndexedDB 按 `attempt_id` 备份，与服务器暂存双写。

### 6.3 阅卷流水线（`grading` Worker）

```text
grading_pipeline(attempt_id):
  for each answer:
    if choice: rule_grade()
    if fill: normalize + rule；模糊则 llm_grade_fill()
    if answer + images: ocr_provider.recognize() → llm_grade_rubric()
    if answer + text: llm_grade_rubric()
  aggregate scores
  emit diagnose_pipeline.delay(...)
```

- 选择题/明确填空 **不走 LLM**（降本降延迟）  
- LLM 输出强制 JSON Schema（得分、采分点、评语）  
- 失败重试：Celery `autoretry`；最终 `needs_review`  

### 6.4 OCR 适配层

```python
class OcrProvider(Protocol):
    async def recognize(self, image_bytes: bytes, hint: str = "math") -> OcrResult
```

- 配置项切换：`ocr_provider=baidu|tencent|easyocr|mathpix`  
- 结果：`text, confidence, raw` 落库  

### 6.5 错题讲解与 Tutor

- 同步返回快照 `analysis`  
- 追问：`POST /student/tutor/sessions` + **SSE 流式**（P2）或一次性返回（P1）  
- Prompt 组装：系统人设 + 题目快照 + 画像摘要 + 安全策略（不闲聊、分层提示）  
- 限流：Redis 令牌桶按 user/day  

### 6.6 诊断 / 路径 / 课程

均为 **交卷成功后的下游任务链**：

```text
grading → diagnose → plan → course_build
```

- 每步写 `job_runs`，学生端「报告生成中」可读进度  
- 路径拓扑：NetworkX 或自研 DFS（依赖少可自研）  
- 课程资源：DB 查询知识点讲义/视频/练习；缺失打标不阻塞

## 7. API 设计约定

| 项 | 约定 |
|----|------|
| 前缀 | 学生：`/api/v1/student`；管理：维持 `/api/...` |
| 鉴权 | `Authorization: Bearer <access_token>` |
| 幂等 | 交卷、组卷关键写操作带 `Idempotency-Key` |
| 错误码 | 业务码 + HTTP 状态；组卷降级返回 `warning` 非硬失败 |
| 分页 | `page/page_size` 与现 Admin 一致 |
| 任务 | `202 Accepted` + `job_id` 或直接挂在资源 `status` 字段 |

## 9. 安全、配额与合规

| 项 | 方案 |
|----|------|
| 鉴权 | 学生 JWT；Admin 独立角色；接口 RBAC |
| 防作弊 | 交卷时间、切屏次数（可选埋点）；题库答案字段权限隔离 |
| 上传安全 | 类型白名单、大小限制、病毒扫描（后期）、私有读 URL |
| LLM 安全 | 输出过滤、未成年人内容策略、不采集敏感个人信息入 Prompt |
| 成本控制 | 用户日调用上限；批改优先规则引擎；缓存高频讲解 |
| 隐私 | 答卷与手写图归属用户；删除账号可级联匿名化 |

## 13. 风险与对策

| 风险 | 对策 |
|------|------|
| 已学范围内题源不足 | 产品已定义降级；技术上返回 `degraded` + 运营补题看板 |
| 手写公式 OCR 不准 | 云 OCR + 置信度阈值 + 学生确认 OCR 文本后再判分（可选） |
| LLM 批改不稳定 | JSON Schema、低温、双次投票（后期）、人工复核队列 |
| 组卷变慢 | 题池预过滤物化视图；禁止全表扫；超时降级 |
| SQLite 生产翻车 | 明确生产必须 PostgreSQL |

## 14. 技术选型决策摘要（给评审）

1. **继续 Python FastAPI 单体模块化 + Celery**，而不是一上来微服务。  
2. **学生端与 Admin 分前端、共后端/共库**，资产不复制。  
3. **PostgreSQL + Redis** 作为生产标配；pgvector 按需启用。  
4. **规则批改优先，LLM/OCR 仅用于填空模糊与解答/手写**。  
5. **测评快照不可变**，保证教学与申诉可回放。
