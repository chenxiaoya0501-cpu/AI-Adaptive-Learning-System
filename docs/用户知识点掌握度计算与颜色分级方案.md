# 用户知识点掌握度计算与颜色分级方案

## 1. 方案目标

本方案用于统一计算某个用户对每个知识点的掌握程度，并为学生端学习地图、能力评估、学习推荐等功能提供一致的数据依据。

算法需要同时解决以下问题：

1. 综合用户针对同一知识点的多轮测试结果。
2. 近期作答比早期作答具有更高权重，但不按照自然天数衰减。
3. 支持选择题、主观题部分得分、主知识点和次知识点。
4. 支持通过知识点前置依赖关系进行有限推断。
5. 防止单题、重复路径或密集关系导致掌握度被过度放大。
6. 同时输出掌握分数、置信度、状态、状态来源和可解释证据。
7. 使用从红色到绿色的稳定颜色体系展示掌握程度。

---

## 2. 核心输出

每个“用户—知识点”生成以下结果：

```json
{
  "user_id": 1,
  "knowledge_point_id": "MATH-01-038",
  "mastery_score": 82.4,
  "confidence": 0.76,
  "status": "mastered",
  "status_source": "combined",
  "direct_positive": 2.31,
  "direct_negative": 0.42,
  "inferred_positive": 0.58,
  "inferred_negative": 0.16,
  "attempt_count": 5,
  "recent_correct_streak": 3,
  "recent_wrong_streak": 0
}
```

### 2.1 掌握分数

`mastery_score` 取值范围为 `0～100`：

- `100`：数学意义上的完全掌握。
- `0`：数学意义上的完全未掌握。
- `50`：正面证据与负面证据基本相当。

实际系统加入中性先验后，分数通常逐渐逼近0或100，不会因为一道题直接达到绝对值。

### 2.2 置信度

`confidence` 取值范围为 `0～1`，表示当前结论的证据充分程度。

掌握分数和置信度必须同时使用：

- 分数高、置信度高：可以稳定判定已掌握。
- 分数高、置信度低：只能判定为倾向掌握或不明确。
- 没有任何证据：状态为尚未测评，不使用50分冒充测评结果。

## 3. 数据输入

### 3.1 有效作答

只纳入以下作答：

- 试卷已完成批改。
- 作答结果能够计算得分率。
- 题目至少关联一个有效知识点。

待人工批改、批改失败和已撤销的作答不进入计算。

### 3.2 单题正确程度

统一使用 `correctness` 表示单题正确程度：

```text
correctness = 实际得分 / 题目总分
```

范围为 `0～1`：

- 完全答对：`1`
- 完全答错：`0`
- 部分得分：按实际得分率计算

### 3.3 知识点角色

一题可以关联多个知识点：

| 角色 | 默认权重 |
|---|---:|
| 主知识点 | 1.0 |
| 次知识点 | 0.5 |

次知识点只提供辅助证据，避免一道综合题对多个知识点产生同等强度的判断。

---

## 4. 多轮测试的轮次权重

时间权重不按自然天数计算，而是按该知识点的有效作答顺序计算。

对每个“用户—知识点”单独排序：

```text
attempt_weight = attempt_decay ^ distance
```

默认参数：

```text
attempt_decay = 0.75
```

其中，`distance` 表示距离最近一次有效作答的序号：

| 作答位置 | distance | 权重 |
|---|---:|---:|
| 最近第1次 | 0 | 1.000 |
| 最近第2次 | 1 | 0.750 |
| 最近第3次 | 2 | 0.563 |
| 最近第4次 | 3 | 0.422 |
| 最近第5次 | 4 | 0.316 |
| 最近第6次 | 5 | 0.237 |

默认只保留最近10次有效作答。超过10次的历史作答不再参与实时计算，但原始记录仍然保留。

“第几次”按该知识点实际出现的作答次数计算，不按整张试卷次数计算。例如某知识点只在第1、3、5张试卷出现，则它只有3次有效作答。

### 4.1 单张试卷证据上限

同一张试卷可能包含多道高度相似的题。为避免单张试卷支配长期状态：

```text
同一试卷、同一知识点的直接证据总权重上限 = 2.0
```

超过上限的证据按比例缩放。

---

## 5. 直接答题证据

每条直接证据的基础权重：

```text
direct_weight
  = attempt_weight
  × knowledge_role_weight
  × difficulty_weight
  × grading_confidence
```

### 5.1 难度权重

| 难度 | 答对侧权重 | 答错侧权重 |
|---|---:|---:|
| 简单 | 0.8 | 1.2 |
| 中等 | 1.0 | 1.0 |
| 困难 | 1.2 | 0.8 |

困难题答对提供更强的正面证据；简单题答错提供更强的负面证据。

如果当前题库难度数据不可靠，第一版统一使用 `1.0`，待难度标注完善后再启用差异权重。

### 5.2 批改可信度

| 批改方式 | 默认权重 |
|---|---:|
| 客观题自动判分 | 1.0 |
| 人工确认 | 1.0 |
| 大模型主观题判分 | 0.85 |
| 低置信度自动判分 | 0.6 |

### 5.3 正负证据计算

考虑答对侧和答错侧难度权重后：

```text
direct_positive += base_weight × correctness × correct_difficulty_weight
direct_negative += base_weight × (1 - correctness) × wrong_difficulty_weight
```

其中：

```text
base_weight
  = attempt_weight
  × knowledge_role_weight
  × grading_confidence
```

## 6. 知识图谱推断

假设：

```text
A → B
```

表示A是B的前置知识点，掌握B通常需要先掌握A。

### 6.1 允许的推断方向

只允许两种推断：

1. A的题答错，可以向后推断B可能尚未掌握。
2. B的题答对，可以向前反推A可能已经掌握。

不能采用以下推断：

1. A答对，不能证明B也掌握。
2. B答错，不能证明A未掌握。

### 6.2 向后传播负面证据

前置知识点答错时：

```text
dependent.inferred_negative
  += prerequisite.direct_negative × forward_factor ^ distance
```

默认：

```text
forward_factor = 0.50
```

### 6.3 向前传播正面证据

后继知识点答对时：

```text
prerequisite.inferred_positive
  += dependent.direct_positive × backward_factor ^ distance
```

默认：

```text
backward_factor = 0.60
```

### 6.4 多跳传播

对于：

```text
A → B → C
```

C产生1.0正面直接证据时：

```text
B获得 1.0 × 0.60 = 0.60 正面推断
A获得 1.0 × 0.60² = 0.36 正面推断
```

A产生1.0负面直接证据时：

```text
B获得 1.0 × 0.50 = 0.50 负面推断
C获得 1.0 × 0.50² = 0.25 负面推断
```

默认最大传播深度为3层。

### 6.5 推断必须从直接证据出发

每轮计算只允许直接作答证据作为传播源。不能将已经推断出来的证据再次作为新的独立证据传播，否则在环形关系或密集图中会形成无限反馈。

实现时，可以从每条直接作答事件出发执行一次有限深度的图遍历。

### 6.6 多路径去重

同一道题可能通过多条路径传播到同一个知识点。针对同一个：

```text
作答记录 + 目标知识点 + 证据方向
```

只保留权重最大的一条路径，不累加所有路径。

### 6.7 推断证据上限

推断只能辅助直接证据，不能压过真实作答：

```text
inferred_total_cap =
  direct_total > 0
    ? max(1.5, direct_total × 0.60)
    : 2.5
```

将正负推断证据按比例缩放到该上限以内。

## 7. 掌握分数计算

使用中性贝叶斯先验：

```text
prior_positive = 0.5
prior_negative = 0.5
```

汇总：

```text
positive =
  prior_positive
  + direct_positive
  + inferred_positive

negative =
  prior_negative
  + direct_negative
  + inferred_negative
```

掌握分数：

```text
mastery_score = positive / (positive + negative) × 100
```

没有任何直接或推断证据时：

```text
mastery_score = null
status = untested
```

不要把无证据状态显示成50分。

---

## 8. 置信度计算

有效证据量：

```text
evidence_strength =
  direct_positive
  + direct_negative
  + inferred_positive
  + inferred_negative
```

基础置信度：

```text
confidence = 1 - exp(-evidence_strength / 3)
```

如果完全没有直接证据，只有关系推断：

```text
confidence = confidence × 0.75
```

如果推断证据只来自一道题或一个相邻知识点：

```text
confidence = confidence × 0.80
```

最终限制在 `0～1`。

---

## 9. 状态判定

### 9.1 有直接作答证据

| 条件 | 状态 |
|---|---|
| 分数 ≥ 75，置信度 ≥ 0.60，最近连续答对 ≥ 2 | 已掌握 |
| 分数 ≤ 40，置信度 ≥ 0.60，最近2次至少有1次错误 | 未掌握 |
| 其他情况 | 不明确 |

一次近期答对不能立即把“未掌握”改成“已掌握”；一次近期错误也不能立即把稳定掌握改成“未掌握”。

推荐状态变化：

```text
错 → 错 → 对 → 对 → 对
未掌握 → 不明确 → 已掌握
```

```text
对 → 对 → 对 → 错
已掌握 → 不明确
```

### 9.2 没有直接答题

没有直接答题的知识点统一保持“尚未测评”，不单独使用关系推断生成掌握分或颜色。关系推断证据只用于修正已经存在直接作答证据的知识点，最终只输出一套综合掌握分。

### 9.3 状态来源

建议保存：

| status_source | 含义 |
|---|---|
| `combined` | 直接作答和知识关系权重合并计算 |
| `none` | 没有证据 |

## 10. 颜色分级

颜色用于表达掌握程度，红色表示未掌握，绿色表示掌握。中间区域采用橙色、黄色和青绿色平滑过渡。

### 10.1 推荐分级

| 掌握分数 | 等级 | 状态文案 | 主色 | 浅色背景 |
|---:|---|---|---|---|
| 0～20 | L1 | 严重未掌握 | `#E5484D` | `#FDEBEC` |
| 21～40 | L2 | 未掌握 | `#F26B38` | `#FFF0E8` |
| 41～59 | L3 | 掌握不明确 | `#E9A323` | `#FFF7D6` |
| 60～74 | L4 | 初步掌握 | `#65AFA2` | `#E8F6F3` |
| 75～89 | L5 | 已掌握 | `#22A884` | `#DDF5ED` |
| 90～100 | L6 | 熟练掌握 | `#087F6A` | `#D5F1E9` |
| 无分数 | L0 | 尚未测评 | `#ADC3C2` | `#FFFFFF` |

其中：

- 理论上的 `0` 使用最明确的红色表达完全未掌握。
- 理论上的 `100` 使用最明确的深绿色表达完全掌握。
- `41～59` 使用黄色，表示正负证据接近。
- `60～74` 使用青绿色，表示正在接近掌握，但证据尚不足。

### 10.2 前端变量

```css

  --mastery-l4: #65afa2;
  --mastery-l5: #22a884;
  --mastery-l6: #087f6a;

  --mastery-l0-bg: #ffffff;
  --mastery-l1-bg: #fdebec;
  --mastery-l2-bg: #fff0e8;
  --mastery-l3-bg: #fff7d6;
  --mastery-l4-bg: #e8f6f3;
  --mastery-l5-bg: #ddf5ed;
  --mastery-l6-bg: #d5f1e9;
}
```

### 10.3 图谱节点样式

建议采用：

- 节点填充：对应等级的浅色背景。
- 节点边框：对应等级的主色。
- 分数或状态标签：使用主色。
- 当前选中节点：在状态色外增加统一深色外环，不改变掌握状态色。
- 所有知识点统一使用实线边框，不再用不同线型区分推断与直接作答。
- 未直接答题的节点使用白色填充。

### 10.4 可访问性

不能只依赖颜色传递状态。节点必须同时展示：

- 状态文案；
- 掌握分数；
- 直接测评或推断标识；
- 必要时增加图标。

色盲或低对比度环境下，用户仍应能够理解状态。

## 11. 计算伪代码

```text
function calculateUserMastery(userId):
    answers = loadAllGradedAnswers(userId)
    relations = loadPrerequisiteRelations()

    directEvents = buildDirectEvidenceEvents(answers)

    for each knowledgePoint:
        events = lastTenEffectiveEvents(directEvents[knowledgePoint])
        assignAttemptWeights(events, decay = 0.75)
        directEvidence[knowledgePoint] = aggregate(events)

    inferredEvidence = empty

    for each directEvent:
        if directEvent.positive > 0:
            ancestors = traversePrerequisites(
                directEvent.knowledgePoint,
                maxDepth = 3
            )
            propagatePositiveBackward(
                directEvent,
                ancestors,
                factor = 0.60,
                keepMaxPath = true
            )

        if directEvent.negative > 0:
            descendants = traverseDependents(
                directEvent.knowledgePoint,
                maxDepth = 3
            )
            propagateNegativeForward(
                directEvent,
                descendants,
                factor = 0.50,
                keepMaxPath = true
            )

    for each knowledgePoint:
        capInferredEvidence(knowledgePoint)

        if no direct or inferred evidence:
            save(status = "untested", masteryScore = null)
            continue

        positive = 0.5 + directPositive + inferredPositive
        negative = 0.5 + directNegative + inferredNegative
        score = positive / (positive + negative) * 100
        confidence = calculateConfidence()
        status = classify(score, confidence, recentStreaks, evidenceSources)

        save(score, confidence, status, evidenceBreakdown)
```

## 12. 数据库存储建议

建议新增用户知识点掌握状态表：

```text
user_knowledge_mastery
```

核心字段：

```text
id
user_id
knowledge_point_id
mastery_score
confidence
status
status_source
direct_positive
direct_negative
inferred_positive
inferred_negative
attempt_count
recent_correct_streak
recent_wrong_streak
direct_source_count
inferred_source_count
last_test_paper_id
calculated_at
created_at
updated_at
```

建议唯一约束：

```text
UNIQUE(user_id, knowledge_point_id)
```

证据明细不必全部塞入状态表。原始答题记录仍作为事实来源，需要解释时可以按用户、知识点重新查询。

## 13. 重新计算时机

以下事件需要触发重新计算：

1. 一张试卷完成批改。
2. 人工修改某道题的批改结果。
3. 题目关联的知识点发生变化。
4. 知识点前置依赖关系发生变化。
5. 算法参数或阈值发生变化。

建议采用后台任务批量重算：

- 批改完成时，只重算受本试卷影响的用户和知识点。
- 关系变化时，重算受影响知识点及其三层上下游节点。
- 参数整体调整时，再执行全量重算。

## 15. 版本与可解释性

每次计算建议保存：

```text
algorithm_version = "mastery-v1"
```

接口应支持返回简要解释，例如：

```json
{
  "mastery_score": 68.5,
  "confidence": 0.71,
  "status": "uncertain",
  "explanation": {
    "recent_attempts": ["wrong", "correct", "correct"],
    "direct_evidence": 2.31,
    "inferred_mastered_from": ["一次函数表达式"],
    "inferred_unmastered_from": ["函数概念"]
  }
}
```

这样教师、学生和运营人员能够理解系统为什么给出某个结论，也便于后续校准参数。
