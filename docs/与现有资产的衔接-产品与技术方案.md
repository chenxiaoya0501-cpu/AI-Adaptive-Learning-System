## 1. 总览：现状 → 消费 → 缺口

| 已有资产 | 当前成熟度（代码事实） | 学生闭环如何消费 | 必须补齐（否则组卷/路径不可用） |
|---------|----------------------|-----------------|--------------------------------|
| 知识点库 `knowledge_points` / `knowledge_relations` | 课标抽取、章节标注、关系抽取、CRUD 可用；`status` 有 draft/reviewed/published 但审核流弱 | 组卷覆盖；路径前置；课程目录 | **章节目录抽取+展示页**；**published 门禁**；掌握度在学生域（另案） |
| 数学题库 `exam_papers` / `questions` | Word 拆题、真题/模拟分流、答案/解析字段、`knowledge_point_ids` JSON **已有但未强制** | 动态组卷题源；标准答案/解析；真题结构模板 | **主知识点强制关联**；**题分值**；**真题 π(k,t) 统计与模板表**；组卷池只读 published |
| 后台 LLM 配置 `system_configs` + `llm_client` | Admin 可配 Key/Model；用于抽取/标注 | 错题追问、OCR 后语义批改、Tutor | **学生会话表**；**画像入 Prompt**；**限流/用途隔离**（抽取 vs 教学） |

```text
┌─────────────────────────────────────────────────────────────┐
│ Admin 建设面（写）                                            │
│  知识点抽取/标注  │  题库上传解析  │  挂知识点  │  模板统计   │
└────────────────────────────┬────────────────────────────────┘
                             │ 只读 API / 同库查询
┌────────────────────────────▼────────────────────────────────┐
│ Student 消费面（读资产 + 写学情）                              │
│  Goal(L) → 组卷快照 → 作答 → 批改 → 掌握度/路径/课程/Tutor    │
└─────────────────────────────────────────────────────────────┘
```

## 2. 资产 A：知识点库衔接

### 2.1 现有能力（可直接复用）

| 能力 | 位置 | 对学生闭环的价值 |
|------|------|-----------------|
| 知识点主数据 | `knowledge_points`：id/domain/category/name/grade/chapter/cognitive_level/status | 组卷归属、路径节点、课程单元键 |
| 前置关系 | `knowledge_relations`（prerequisite 等）+ 字段 `prerequisites` | 路径补前置；组卷题源不足时放宽到前置点 |
| 章节线索 | `grade` + `chapter`（教材标注写入） | 与「章节目录」匹配展示关联数 |
| 管理 API | `/api/knowledge/points|relations|stats|annotate-chapters` | Admin 继续建设；Student 另开只读接口 |

### 2.2 产品缺口与补齐方案

#### 缺口 A1：章节目录应从电子课本抽取（Admin）

**问题**：仅从知识点上的 `grade/chapter` 反推目录，易乱、缺章。

**产品方案（定稿）**：

1. **抽取入口**：在「知识抽取」增加任务类型 **「章节目录抽取」**，源文件选已上传的教材 PDF（复用现有章/节解析能力）  
2. **展示入口**：在「知识图谱管理」下新增子栏目 **「章节目录」**，用于查看、编辑（改名/删噪/排序）最终目录  
3. 章与知识点：可通过 KP 上的 `chapter` 与目录章名匹配，展示每章关联点数；不对齐时支持后续手工绑定  
4. **明确不做（本衔接）**：学生端勾选已学章节 —— 属学生业务，另案处理  

**菜单结构**：

```text
知识图谱管理
  · 图谱概览 / 知识点管理 / 关系管理
  · 资料上传
  · 知识抽取          ← 任务类型增加「章节目录抽取」
  · 章节目录          ← 新增：展示与编辑抽取结果
```

**验收**：教材跑完抽取任务后，「章节目录」页可见并可以编辑章列表。

#### 缺口 A2：掌握度不应写在知识点主表

**问题**：掌握度是「学生对点」的学情，多用户不同；不能污染 `knowledge_points`。

**产品方案**：

- 学生域新建 `student_kp_mastery(user_id, kp_id, mastery, confidence, updated_at)`（学生业务阶段再做）  
- 诊断报告引用 KP 名称/分类时 **join 知识点库只读**  

#### 缺口 A3：可用性门禁

**产品规则**：

| 用途 | 知识点状态要求 |
|------|----------------|
| 组卷覆盖 / 对外可用 | `status = published`（过渡期可含 reviewed） |
| Admin 编辑中 | draft 不进入组卷池 |

### 2.3 技术实现方案

#### 2.3.1 章节目录（抽取任务 + 展示页）

**数据**：`textbook_chapters`（或 `chapter_catalog`）——绑定 `uploaded_file_id`、grade、semester、有序章/节、可编辑字段。

**抽取**：

- `ExtractionTask.task_type = chapter_toc_extraction`（展示名：章节目录抽取）  
- Worker：读教材 PDF → 章/节正则（复用 `chunk_textbook_pdf` 识别逻辑）→ 写入章节表  
- 任务列表展示进度；完成后在「章节目录」页可见  

**展示页 API（Admin）**：

| 方法 | 说明 |
|------|------|
| GET | 按教材/年级列出目录树 |
| PUT | 改名、排序、删除节点 |
| GET | 每章关联 KP 数量（按 chapter 字段匹配） |

**不做**：`/api/v1/student/chapters` 等学生勾选接口（本衔接不含）。

#### 2.3.2 与知识点的衔接（后台）

- 现有「年级段/章节标注」继续往 KP 写 `grade`/`chapter`  
- 「章节目录」页展示匹配到的 KP 数；支持后续手工绑定表（可 P1）  

#### 2.3.3 章节相关 Admin 改造清单

| 项 | 说明 | 优先级 |
|----|------|--------|
| 知识抽取增加「章节目录抽取」 | 选教材文件启动任务 | P0 |
| 侧栏「章节目录」页 | 查看/编辑目录 | P0 |
| 批量发布知识点 | draft→published | P0 |
| 关系质检 | 环依赖等 | P1 |

## 3. 资产 B：数学题库衔接

### 3.1 现有能力（可直接复用）

| 能力 | 位置 | 价值 |
|------|------|------|
| 试卷与题目 | `exam_papers` / `questions` | 题源、解析、真题/模拟分流 |
| 题型 | `question_type`：choice/fill/answer/proof | 对齐真题大题结构 |
| 答案/解析 | `answer` / `analysis` | 批改与错题讲解 |
| 弱关联 | `knowledge_point_ids` JSON | **需升级为强制主知识点** |
| 能力维度字段 | `ability_dimension` | 诊断雷达（多数题目前为空，需补） |
| 分值字段 | `score` 可空 | 模板统计与组卷需要补全 |
| 图片 | `images` + `/uploads/...` | 快照时复制路径或转存 |

### 3.2 产品缺口与补齐方案

#### 缺口 B1：题目强制关联知识点

**产品规则**：

1. 每题必须有 **一个主知识点** `primary_kp_id`  
2. 可有次要 `secondary_kp_ids[]`（讲解/检索用；组卷计分归主知识点）  
3. 无主知识点的题：**不得进入动态组卷池**；可在「练习随便刷」中降级使用（可选）  
4. 后台提供：单题编辑挂载、按卷批量挂载、覆盖率仪表盘（按卷/按章）  

**挂载方式（产品优先级）**：

| 方式 | 适用 | 说明 |
|------|------|------|
| 人工标注 | 质量基线 | 真题优先人工或半自动 |
| LLM 辅助建议 | 提效 | 给出 Top3 KP，人工确认后写入 |
| 规则/检索 | 初筛 | 题干关键词 ↔ KP name 相似度 |

#### 缺口 B2：真题分值与知识点占比统计

**产品产出物**：

1. **地区默认分值表**（如浙江中考数学）：题型默认分、解答题题号分值表  
2. **单卷结构模板**：题型题量 + 分值  
3. **π(k)、π(k,t)**：卷内主知识点分值占比  
4. **默认模板**：多套真题等权平均或指定「官方模板卷」  

运营在 Admin「试卷管理」增加：

- 「应用默认分值」  
- 「生成/刷新结构模板」  
- 「查看知识点分值占比」  

#### 缺口 B3：模拟卷结构对齐

**产品规则**：

- 动态 **诊断/阶段测**：题源默认 `bank_type=real`（可配置）  
- 课程练习/微测：优先 `mock`  
- 模拟题同样要求挂主知识点；**不要求**单独生成模板，组卷结构仍套用真题模板  

#### 缺口 B4：答卷快照（跨资产）

每次组卷将入选题目 **深拷贝** 到 `test_questions`（题干/选项/答案/解析/图/分值/主 KP），与题库后续编辑解耦。

### 3.3 技术实现方案

#### 3.3.1 模型升级（兼容迁移）

```text
questions 表变更：
  + primary_kp_id VARCHAR(50) NULL FK → knowledge_points.id   -- P0 先可空，组卷过滤非空
  + secondary_kp_ids JSON
  -- knowledge_point_ids 保留一段时间：迁移脚本把 [0] 写入 primary_kp_id
  score：组卷前校验；空则用模板题型默认分回填到快照（不强制改原题）
```

索引建议：

```text
(subject via paper join), bank_type, question_type, primary_kp_id, status
```

因 `subject` 在 `exam_papers`，组卷查询用 join 或冗余 `questions.subject`。

#### 3.3.2 新表

```text
exam_score_schemes          # 地区默认分值方案
  id, exam_type, subject, region, name, rules JSON, is_default

exam_structure_templates
  id, name, exam_type, subject, region, year
  source_paper_ids JSON
  type_structure JSON       # [{question_type, count, score_each|per_number}]
  scheme_id, is_default

exam_kp_score_stats
  template_id, kp_id, question_type
  score_sum, score_ratio    # π(k,t)
  question_count
```

#### 3.3.3 统计任务

```text
POST /api/questions/papers/{id}/build-template
  1. 读卷内题目；分值空 → 套 scheme
  2. 校验 primary_kp_id 覆盖率；低于阈值则拒绝或标记 incomplete
  3. 聚合 type_structure + π(k,t)
  4. upsert template / stats
```

也可 Celery 定时对所有 `paper_type=real AND parse_status=parsed` 刷新。

#### 3.3.4 组卷只读查询契约

```python
def fetch_pool(L, qtype, bank_types, exclude_ids):
    return questions where
      primary_kp_id in L
      and question_type == qtype
      and bank_type in bank_types
      and status in ('published','reviewed')  # 过渡
      and id not in exclude_ids
      and answer is not null   # 诊断卷建议
```

#### 3.3.5 Admin API / UI 增补

| 能力 | API/页面 |
|------|----------|
| 挂载主知识点 | `PUT /questions/{id}` 扩展字段；列表筛选「未挂载」 |
| 批量建议挂载 | `POST /questions/suggest-kp`（LLM，写建议不直写） |
| 覆盖率 | `GET /questions/coverage?paper_id=` |
| 模板 | `POST .../build-template`，`GET /templates` |
| 测评监控 | 学生测卷列表（P1）只读 |

#### 3.3.6 快照写入

```python
TestQuestion(
  content=q.content, options=q.options, answer=q.answer, analysis=q.analysis,
  images=q.images, score=resolved_score,
  primary_kp_id=q.primary_kp_id,
  source_question_id=q.id,
)
# 图片：快照保留原 URL；或 copy 到 tests/{test_id}/ 防原卷删除导致挂图
```

**产品建议**：删除试卷时若存在关联历史快照，改为软删除题库题，文件延迟清理。

## 4. 资产 C：后台 LLM 配置衔接

### 4.1 现有能力

| 能力 | 位置 | 现状 |
|------|------|------|
| 配置项 | `system_configs`：llm_api_key/base_url/model/temperature/max_tokens | Admin UI 可改 |
| 客户端 | `services/llm_client.py` → `extract_json` | 偏抽取场景 |
| 用途 | 知识点抽取、章节标注、（未来）KP 建议 | 尚无学生会话 |

### 4.2 产品缺口与补齐

| 缺口 | 产品方案 |
|------|----------|
| 学生会话 | Tutor/追问/批改说明独立会话实体，可按题/按单元回溯 |
| 认知画像入 Prompt | 注入 mastery 摘要、能力雷达弱项、年级与目标，限制剧透级别 |
| 用途隔离 | 抽取用低温 JSON；教学用可略高温度；日限额分用途 |
| 安全 | 未成年人场景拒闲聊；不把手机号等 PII 送模型 |

### 4.3 技术实现方案

#### 4.3.1 配置扩展（仍用 system_configs 或拆 profile）

```text
llm_api_key / llm_base_url / llm_model          # 默认
llm_grade_model / llm_tutor_model              # 可选覆盖
llm_tutor_temperature = 0.3
llm_grade_temperature = 0.0
student_llm_daily_token_limit
ocr_provider / ocr_api_key                     # 与 LLM 并列
```

#### 4.3.2 客户端扩展

```python
# 在现有 LLMClient 上扩展，勿另起一套
async def chat(self, messages, *, temperature=None, stream=False) -> str
async def chat_json(self, messages, schema: dict) -> dict  # 批改采分点
```

用途枚举：`Purpose = extraction | kp_suggest | grading | tutor | analysis_gen`  
每次调用写 `llm_call_logs(purpose, user_id?, tokens, latency, ok)`（P1 可先打日志文件）。

#### 4.3.3 学生会话模型

```text
tutor_sessions(id, user_id, context_type, context_id, goal_id, created_at)
tutor_messages(id, session_id, role, content, created_at, meta JSON)
```

`context_type`：`wrong_question` | `course_unit` | `general`  
Prompt 组装器 `TutorPromptBuilder.build(session, student_profile, asset_snapshot)`。

#### 4.3.4 与批改/OCR 的衔接

```text
手写图 → OcrProvider（独立适配，不复用 pdf EasyOCR 流程）
      → ocr_text 写入 test_answers
      → LLM grading（标准答案 + 解析 + ocr_text）
```

LLM 配置与 OCR 配置分离；批改失败可降级 `needs_review`。

## 5. 三资产协同：端到端数据流

### 5.1 章节目录（Admin）

```text
资料上传（教材 PDF）
        ↓
知识抽取 · 章节目录抽取
        ↓
textbook_chapters 入库
        ↓
「章节目录」页查看 / 编辑
        ↓（可选）与 KP.chapter 匹配显示关联数
```

> 学生勾选已学章 → 展开 L：不在本衔接范围，学生业务另案。

### 5.2 动态组卷

```text
已挂 primary_kp 的题池 + exam_structure_templates
        ↓ assembly
test_papers + test_questions（快照）
```

### 5.3 批改与讲解

```text
test_answers + 快照.answer/analysis
 + OCR? + LLM(system_configs)
        ↓
得分明细 → 错题展示快照.analysis → 追问（学生业务）
```

### 5.4 诊断与路径/课程

```text
答题结果 × π(k) × knowledge_relations
        ↓
mastery / path / course（学生业务阶段；读同一套 KP/题库）
```

## 6. 权限与读写边界

| 资产 | Admin | Student API |
|------|-------|-------------|
| knowledge_points | CRUD / 抽取 | 只读 published |
| knowledge_relations | CRUD | 只读 |
| exam_papers / questions | CRUD / 解析 / 挂载 / 模板 | 组卷时服务端读；**永不把未交卷的 answer/analysis 返回答题页** |
| system_configs LLM | 读写 | 不可见；仅服务端使用 |
| student_kp_mastery / tests / tutor | 只读监控（P1+） | 学生读写自己的数据 |

答题页 Schema：`ExamQuestionPublic`（无 answer/analysis）  
结果页 Schema：`ExamQuestionReview`（含解析）。

## 7. 质量门禁（资产就绪定义 Done）

组卷上线前，资产侧建议同时满足：

| 指标 | 建议阈值（可调） |
|------|------------------|
| 目标年级章目录非空 | 100% 有章可勾 |
| 真题卷主知识点挂载率 | ≥ 90%（按题数） |
| 挂载 KP 属于 published | 100% |
| 默认模板存在 | 每考区至少 1 套 is_default |
| 模板题型题量与样卷一致 | 人工确认 |
| 诊断题源在 \(L\) 试算 | 各题型缺口 &lt; 20% 或可降级披露 |
| 解析非空率（真题） | ≥ 80%（讲解体验） |

Admin 做「资产健康仪表盘」展示上述指标。
